# Auto Input 출시 QA 체크리스트

최종 업데이트: 2026-06-08

## 목적

출시 직전에 로그인, 결제, 확장프로그램, PC 앱 실행, 예시 사이트까지 한 번에 점검하기 위한 체크리스트다. 아래 항목 중 치명적인 항목이 실패하면 출시를 보류한다.

## 1. PC 앱 기본 실행

- [ ] 최신 설치 파일로 Auto Input을 설치한다.
- [ ] 앱 실행 시 콘솔 창이 뜨지 않는다.
- [ ] 첫 실행 시 Google 로그인 안내가 바로 표시된다.
- [ ] Google 로그인 완료 후 앱에 계정 정보가 반영된다.
- [ ] 로그아웃 후 다시 로그인할 수 있다.
- [ ] 앱 재실행 후 기존 프로젝트와 플랜 상태가 유지된다.

## 2. 예시 프로젝트

- [ ] `예제로 시작하기` 또는 `예시 프로젝트 만들기` 클릭 시 프로젝트가 생성된다.
- [ ] 대상 URL이 `https://auto-web-8f2de.web.app/demo-customer`로 설정된다.
- [ ] 기본 매핑 selector가 올바르게 들어가 있다.
- [ ] 고객명 입력창 selector가 `#customer-name`이다.
- [ ] 전화번호 입력창 selector가 `#customer-phone`이다.
- [ ] 저장 버튼 selector가 `button.save`이다.
- [ ] `대상 페이지 열기` 클릭 시 앱 내부가 아니라 기본 브라우저가 열린다.
- [ ] 예시 데이터 컬럼 `name`, `phone`이 표시된다.
- [ ] 플로우 화면 하단에 데이터 컬럼 칩이 표시된다.
- [ ] 컬럼 칩 클릭 시 입력값에 컬럼명이 들어간다.

## 3. 확장프로그램

- [ ] 확장프로그램을 설치하거나 새로고침한다.
- [ ] 일반 사이트 방문만으로 권한 요청이 반복 표시되지 않는다.
- [ ] 일반 사이트 방문만으로 `ws://localhost:4173/ws` 콘솔 오류가 반복되지 않는다.
- [ ] 매핑 모드 시작 시에만 현재 사이트 권한을 요청한다.
- [ ] 권한 승인 후 입력창과 버튼을 클릭하면 PC 앱 매핑 목록에 추가된다.
- [ ] 매핑 모드 종료 시 페이지 커서와 테두리 표시가 정상 복구된다.
- [ ] 매핑 요소 삭제 버튼 클릭 시 해당 요소가 삭제된다.
- [ ] 삭제된 매핑을 참조하던 실행 단계가 함께 제거된다.

## 4. 데이터 업로드

- [ ] CSV 파일을 업로드할 수 있다.
- [ ] XLSX 파일을 업로드할 수 있다.
- [ ] XLS 파일을 업로드할 수 있다.
- [ ] 첫 행이 컬럼명으로 표시된다.
- [ ] 빈 컬럼명이나 중복 컬럼명이 있어도 앱이 깨지지 않는다.
- [ ] 업로드된 데이터 미리보기 테이블이 표시된다.
- [ ] 새 데이터 업로드 후 순차 실행의 다음 행 인덱스가 초기화된다.

## 5. 플로우 구성

- [ ] 매핑 화면과 플로우 화면이 분리되어 있다.
- [ ] 입력 단계 추가가 가능하다.
- [ ] 클릭 단계 추가가 가능하다.
- [ ] 대기 단계 추가가 가능하다.
- [ ] 단계 삭제가 가능하다.
- [ ] 단계 전체 비우기가 가능하다.
- [ ] 대상 매핑이 없는 상태에서 단계를 추가해도 앱이 깨지지 않는다.
- [ ] 프로젝트별 실행 방식으로 자동화 또는 단축키를 선택할 수 있다.

## 6. 실행 및 중지

- [ ] 1건 테스트 실행이 가능하다.
- [ ] 전체 데이터 실행이 가능하다.
- [ ] 실행 중 상단 바에 `중지` 버튼이 표시된다.
- [ ] 실행 탭에도 `중지` 버튼이 표시된다.
- [ ] 데모 실행 중 `중지` 클릭 시 반복 실행이 멈춘다.
- [ ] 실제 웹페이지 실행 중 `중지` 클릭 시 확장프로그램으로 중지 요청이 전달된다.
- [ ] 실행 완료 후 `중지` 버튼이 사라진다.
- [ ] 실행 로그에 성공, 실패, 중지 상태가 표시된다.

## 7. 단축키 실행

- [ ] 프로젝트별 실행 방식으로 단축키를 선택할 수 있다.
- [ ] 프로젝트당 단축키 플로우 3개가 표시된다.
- [ ] 각 단축키 플로우가 독립적으로 저장된다.
- [ ] 단축키 3개를 저장해도 앞선 단축키가 마지막 값으로 덮어써지지 않는다.
- [ ] 실행 후 다음 데이터로 이동할지 여부를 선택할 수 있다.
- [ ] 앱이 백그라운드에 있어도 전역 단축키가 동작한다.

## 8. Firebase 및 계정

- [ ] Google 로그인 계정 정보가 앱에 표시된다.
- [ ] 라이선스 새로고침이 동작한다.
- [ ] 무료 플랜의 프로젝트 2개 제한이 적용된다.
- [ ] 7일 무료체험을 시작할 수 있다.
- [ ] 무료체험 시작 후 프로젝트 제한이 해제된다.
- [ ] 무료체험은 계정당 1회만 시작된다.
- [ ] Firestore `licenses/{uid}` 문서와 앱 상태가 일치한다.

## 9. 결제

- [ ] Pro 결제 버튼 클릭 시 NicePay 결제 페이지가 기본 브라우저로 열린다.
- [ ] 결제 완료 페이지에서 앱으로 돌아가 새로고침하라는 안내가 크게 표시된다.
- [ ] 결제 실패 페이지에서 사용자가 다음 행동을 알 수 있다.
- [ ] 결제 완료 후 라이선스 새로고침으로 Pro 상태가 반영된다.
- [ ] 운영 환경에서 테스트용 샌드박스 키가 노출되지 않는다.

## 10. 웹사이트 및 배포

- [ ] `https://auto-web-8f2de.web.app` 접속이 가능하다.
- [ ] 다운로드 링크가 최신 설치 파일을 가리킨다.
- [ ] 테스트 사이트 `https://auto-web-8f2de.web.app/demo-customer` 접속이 가능하다.
- [ ] 확장프로그램 설치 안내 페이지 접속이 가능하다.
- [ ] 개인정보처리방침 접속이 가능하다.
- [ ] 이용약관 접속이 가능하다.
- [ ] 문의 이메일 `bullandbear107@gmail.com`이 노출된다.

## 11. Chrome Web Store 제출

- [ ] 확장프로그램 ZIP 최신 버전을 생성한다.
- [ ] 아이콘 16, 32, 48, 128 크기가 포함되어 있다.
- [ ] 스크린샷을 최소 1개 이상 등록한다.
- [ ] 단일 목적 설명을 입력한다.
- [ ] `activeTab` 권한 사용 이유를 입력한다.
- [ ] `scripting` 권한 사용 이유를 입력한다.
- [ ] `storage` 권한 사용 이유를 입력한다.
- [ ] 원격 코드 미사용 또는 사용 이유를 명확히 입력한다.
- [ ] 개인정보 처리 인증을 체크한다.
- [ ] 게시자 연락처 이메일 인증을 완료한다.
- [ ] 심사 제출을 완료한다.

## 12. 출시 판단 기준

아래 조건이 모두 충족되면 소프트 런칭이 가능하다.

- [ ] 로그인, 예시 프로젝트, 매핑, 실행, 중지 흐름이 끊기지 않는다.
- [ ] 결제 전환과 라이선스 반영 흐름이 확인되었다.
- [ ] 설치 및 확장프로그램 안내가 사용자가 따라 할 수 있을 만큼 명확하다.
- [ ] 치명적인 콘솔 오류나 앱 크래시가 없다.
- [ ] 문의 받을 이메일과 개인정보처리방침이 준비되어 있다.

- [ ] Chrome Web Store 심사 상태를 확인한다.
- [ ] 첫 사용자 피드백을 `즉시 수정`, `다음 주 개선`, `보류`로 분류한다.
